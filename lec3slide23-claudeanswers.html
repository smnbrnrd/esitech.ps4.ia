Diagnosing Neural Network Training Problems

Common symptoms when training a (deep) neural network, with possible causes and potential solutions.

1. The training loss is decreasing nicely, but the validation loss is not

Primary diagnosis: overfitting. The network is memorizing the training data instead of generalizing.

Possible causes:

  • Model too large relative to the amount of data
  • Training for too long
  • Training data not representative
  • Distribution shift between train and validation: bad split, temporal leakage, different preprocessing between the two sets (a common bug)

Solutions:

  • Regularization: weight decay, dropout
  • Early stopping
  • Data augmentation
  • Reduce model capacity
  • Collect more data
  • Check the consistency of the train/validation split and preprocessing

2. The training loss is decreasing, but very slowly

Primary diagnosis: learning rate too low.

Possible causes:

  • Learning rate too small
  • Poor weight initialization
  • Unnormalized data (features on very different scales)
  • Network too deep without mechanisms that ease gradient flow
  • Vanishing gradients (saturating activations such as sigmoid/tanh in a deep network)

Solutions:

  • Increase the learning rate (or run a learning rate range test)
  • Normalize the inputs
  • Switch to ReLU/GELU activations
  • Use an adaptive optimizer (Adam)
  • Add batch normalization or residual (skip) connections

3. The training loss is oscillating a lot, global trends are unclear (training instability)

Primary diagnosis: learning rate too high — the optimizer "jumps over" the minima.

Possible causes:

  • Learning rate too large
  • Batch size too small (very noisy gradients)
  • Outliers or poorly cleaned data
  • Exploding gradients

Solutions:

  • Reduce the learning rate
  • Add a scheduler (warmup + decay)
  • Increase the batch size
  • Gradient clipping
  • Check for outliers in the data

Teaching note: a per-batch loss always oscillates somewhat. Look at a moving average or the per-epoch loss before concluding there is genuine instability.

4. The training loss is not decreasing (the network is not learning)

Primary diagnosis: suspect a bug first, before blaming hyperparameters.

Possible causes (bugs):

  • Shuffled or misaligned labels
  • Gradients not propagating: frozen layer, stray detach(), missing optimizer.step()
  • Loss function unsuited to the task
  • Learning rate set to zero or absurdly small

Possible causes (if the code is correct):

  • Inappropriate learning rate
  • Degenerate initialization (all weights at zero → symmetry never broken)
  • Dead activations (dying ReLU)
  • Task genuinely impossible (no signal in the features)

Solutions and diagnostic best practices:

  • Check that you can overfit a tiny subset (e.g., 10 examples). If the network cannot, it is almost certainly a bug.
  • Compare the initial loss to its theoretical value: e.g., ln(10) ≈ 2.3 for 10 equiprobable classes with cross-entropy. If it starts elsewhere, something is wrong.
  • Review the training loop and the data pipeline line by line.

5. The training loss is increasing

The most suspicious case.

Possible causes:

  • Learning rate far too large: divergence — the loss blows up, sometimes to NaN
  • Sign error: the loss is being maximized by mistake (e.g., wrong convention on the log-likelihood)
  • Gradients applied in the wrong direction
  • Missing optimizer.zero_grad() (gradient accumulation)
  • Exploding gradients in recurrent or very deep networks

Solutions:

  • Drastically reduce the learning rate
  • Check the sign and definition of the loss
  • Gradient clipping
  • Review the training loop line by line
  • If the loss goes to NaN: look for numerical instabilities (log(0), division by zero, NaNs in the data)

Summary

  • The learning rate shows up in almost every case: too small → slow learning; too large → oscillations or divergence. It is the number-one hyperparameter to tune.
  • Recommended debugging approach: start simple (small model, small data subset that you should be able to overfit), then scale up progressively.
